# 消息引用回复

点击自己或对方已发出消息旁的“回复”按钮，在编辑器上方选择引用目标。回复可以包含文字、图片或图文；不能只发送引用。取消或替换引用保留当前正文与图片，切换功能区也保留草稿。排队、上传中和发送失败的消息暂不提供回复入口。

引用卡片保存原消息 ID、作者关系、最多 200 个 Unicode 字符的正文摘要和图片数量，不包含原图片或读取凭证。引用回复只引用目标本身的正文，不嵌套其引用。点击卡片会在当前页面历史内展开并定位原消息；刷新后历史缺失时，只显示缺失提示，不请求历史恢复。原图片过期不影响摘要。

## 协议与兼容

- 无引用的纯文字仍使用 `chat`，无引用的图文仍使用 `chat-rich` version 1。
- 引用使用 `chat-rich` version 2，包含现有 `blocks`、`images` 及必填 `reply`。`reply` 仅接受 `messageId`、`author`、`text`、`imageCount`；`author` 的 `sender` / `recipient` 相对于这条回复的发送者。
- 通过独立的 `chat-reply-capabilities` version 1（`replies: true`）协商，不改变图片能力声明。能力未知时等待，明确不支持时提示对方刷新；同步拒绝发送保留草稿，不降级丢弃引用。
- 发送与图片上传重试保留同一消息 ID、引用快照及已上传资源。正文继续使用既有回执和去重。引用不额外上传或下载原图片，不延长图片有效期。
- 关闭或替换连接时，先撤销全部通道引用再通知能力变化，避免状态订阅同步重发到旧通道。

## 本地验证

```sh
pnpm test
pnpm check
pnpm exec tsc -p tsconfig.e2e.json
pnpm exec tsc -p tsconfig.test.json
pnpm build
pnpm exec playwright test --config playwright.config.ts
```

固定构建验收时，先运行 `pnpm build`，在另一个终端运行 `pnpm exec vite preview --host 127.0.0.1 --port 8787`，再执行 Playwright。现有配置会复用该预览服务；此时测试的是打包产物与本地 Worker、DO、R2，不是线上站点。

客户端单测覆盖协议白名单、Unicode 截断、作者转换、独立能力协商、卡片安全转义，以及旧连接退出时的回调隔离。`e2e/chat-reply.spec.ts` 覆盖双方回复、单层快照、草稿及快捷键、历史分页定位与刷新后缺失、旧端兼容、图片上传重试、重复正文和 ICE 恢复；现有浏览器回归继续覆盖信令短断、租约过期、文件和媒体保留。

无需新增 Worker 接口、R2 配置或服务端状态。部署前按仓库双账号规则核对目标，提交、构建生效和线上功能验收分别记录。
